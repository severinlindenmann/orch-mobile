  `text.json`, `section_text.json`, `index.json`), host section 11A.14 (#465), core develop at `c50e7cff26e7975f7872e7a190579775300bf2d3`
  (last commit touching the f1 vectors directory: `e07e70be97bb810ec70fb2c6f99d77468e0159b7`).
- Copied: 2026-10-15, unmodified. Re-copy together and update this note; never edit by hand.
- Consumed by tests today: `phone_events.json` (accepted cases byte-exact, refused cases' signatures), `hashes.json` (`question_id`, `question_hash`,
  `question_hash_refused`), `labels.json`, `text.json`, `questions.json` (every `question.asked` qid/hash against the model's verdict).
- Vendored for future use, not yet read by a test: `signatures.json`, `section_text.json` (section/body.md rules: the phone is title-only in R2),
  `index.json`, and the other `hashes.json` groups (artifact, section, value, people, policy, grant secret).
- `text.json` (`lone_surrogate`) and `hashes.json` (`value_hash_refused`) contain a lone UTF-16 surrogate escape that a Swift string cannot hold. The
  loader replaces the escape with U+FFFD before parsing; the `lone_surrogate` text case is skipped by name and `value_hash_refused` is simply not tested.
- The Unicode 16.0 tables in `Sources/OrchProtocol/Unicode16Data.swift` are generated by `Scripts/gen_unicode16_swift.py` from orch-core
  `src/orch/canon/_unicode16.py` at `b9d87df4ee88a43b14c74199668e443bafe817a4`.
- Regenerate with `python3 OrchKit/Scripts/gen_unicode16_swift.py <core _unicode16.py> <core sha>`; `--check` fails if the file drifted (run it in CI
  against the pinned core checkout whenever the tables or the pinned commit change). `Unicode16Data.digest` is also checked by a unit test.
